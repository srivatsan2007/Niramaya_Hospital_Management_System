1. SOFTWARE COMPONENTS
--------------------------------------------------------------------------------
The Niramaya Smart Hospital Management System is built on a high-throughput,
zero-bloat stack leveraging native Java standard APIs, cloud-native storage,
and modern standards-compliant web technologies.

A. Core Backend Runtime & Web Server:
   - Java Development Kit (JDK 21 LTS / 25): Provides language runtime, JVM
     performance optimizations, memory management, and modern concurrency.
   - Built-in HTTP Engine (com.sun.net.httpserver.HttpServer): Lightweight native
     HTTP server embedded directly within the JDK. Replaces heavy external
     containers (like Tomcat, GlassFish, or Spring Boot) for fast boot time
     (<1.5s) and minimal memory footprint (<60 MB).
   - Concurrency Manager (java.util.concurrent.Executors): Fixed Thread Pool of
     8 concurrent worker threads handling parallel client requests and REST APIs.
   - Static Asset Dispatcher: Custom StaticFileHandler with path-traversal
     protection serving static assets (HTML/CSS/JS/PNG) and generated reports.

B. Database Persistence & Resilience Layer:
   - Cloud Database: Neon Serverless PostgreSQL (PostgreSQL 16+ via JDBC 42.7.3)
     utilizing SSL-encrypted transport (sslmode=require).
   - Local Offline Failover Database: Embedded SQLite 3.45.1.0 (file-backed
     niramaya_hospitals.db) for zero-config immediate fallback when network
     connectivity is interrupted.
   - JDBC Drivers:
     * org.postgresql:postgresql:42.7.3 (PostgreSQL Cloud Driver)
     * org.xerial:sqlite-jdbc:3.45.1.0 (SQLite Embedded In-Process Driver)
     * com.mysql.cj.jdbc.Driver (MySQL compatibility layer)
   - Dynamic JDBC Reflection Proxy: java.lang.reflect.Proxy wrapper that
     intercepts Statement and PreparedStatement calls, automatically tracks
     execution durations, records SQL exceptions, and coordinates cloud-to-local
     failovers.

C. Frontend Presentation Layer:
   - Standard HTML5: Semantic, accessible web layouts across 8 role portals.
   - Modern CSS3 Design System: Custom CSS variable tokens, glassmorphism card
     treatments, vibrant status pills, and CSS Grid/Flexbox layouts. Zero reliance
     on external bulky CSS frameworks like Tailwind or Bootstrap.
   - Vanilla ES6+ JavaScript: Native fetch() API for JSON consumption, DOM
     manipulation, dynamic filtering, modal managers, and receipt printing.
   - Responsive Navigation (mobile-responsive.js): Touch-friendly sliding side
     drawer, 44px min tap targets, and adaptive viewport breakpoints.
   - Session Telemetry & Digital Clock (live-clock-logger.js): Real-time bottom
     telemetry bar showing session duration, active role, and system timestamp.
   - Staff ID Generator (staff-id-card.js): Canvas/SVG-based printable employee
     identity cards with automated barcode rendering.

D. Desktop GUI Client:
   - Java Swing & AWT (javax.swing.*, java.awt.*): Standalone cross-platform
     desktop interfaces (DoctorDashboardSwing, AdminDashboardSwing,
     NurseDashboardSwing, PharmacyDashboardSwing, LabDashboardSwing,
     OnlineConsultationSwing) for offline hospital desktop terminals.

E. Document & Invoice Generation Services:
   - PDFGenerator & PDFInvoiceGenerator: Automated generation of NABL-standard
     pathology reports and GST-compliant tax invoices into printable HTML and PDF
     formats, saved in Reports/ and public/Reports/.
   - QRCodeGenerator: Generates QR codes for fast order scanning at pharmacy desks.

F. DevOps, Build & Cloud Deployment:

3. PROPOSED SYSTEM
--------------------------------------------------------------------------------
A. Problem Statement:
   Traditional healthcare facilities often rely on fragmented paper files,
   standalone legacy billing tools, disconnected pharmacy inventories, and
   isolated lab reporting systems. This results in:
   - Long patient waiting queues at reception and billing desks.
   - Transcription errors and lost patient medical histories.
   - Pharmacy dispensing delays and expired drug inventory wastage.
   - Unsynchronized inpatient vital monitoring and delayed emergency response.
   - System failure whenever cloud internet connectivity fluctuates.

B. The Proposed Solution — Niramaya Smart Hospital Platform:
   Niramaya provides a unified, real-time healthcare management system:
   1. Unified 7-Role Connected Workspaces:
      Provides dedicated portals for Patients, Doctors, Nurses, Pharmacists,
      Lab Technicians, Reception/Billing Desks, and Administrators.
   2. Dual-Database High Availability:
      Connects to Neon Serverless PostgreSQL in the cloud and automatically
      falls back to embedded SQLite locally when offline, guaranteeing 100% uptime.
   3. Real-Time Counter Billing & Receipt Unlocking:
      Patients booking offline can choose "Pay at Counter". An unpaid ticket is
      generated, and receipt access is locked until reception staff marks the
      fee collected in the Admin Console, which triggers real-time receipt unlocking.
   4. Automated Closed-Loop Clinical Workflow:
      A doctor's consultation automatically routes prescribed medications to the
      central Pharmacy queue and diagnostic investigations to the Laboratory queue.
   5. Inpatient Ward Hub & Emergency SOS:
      Enables real-time vital charting, Medication Administration Records (MAR),
      and an instant 1-click Emergency SOS broadcast across clinical stations.
   6. Integrated Telemedicine Suite:
      Provides browser-based virtual video consultations with consultation timers,
      patient history review, and electronic prescription generation.

6. ALGORITHM OF EVERY MODULE USED
--------------------------------------------------------------------------------

Module 1: Dual-Database Failover & Recovery (DBConnection.java)
---------------------------------------------------------------
1. Check cooldown: Has 60,000 ms elapsed since the last cloud PostgreSQL error?
2. If yes or if PostgreSQL is active:
   a. Attempt connection to POSTGRES_URL with a 5-second timeout.
   b. Execute "SELECT 1" health check.
   c. If successful, set isPostgreSQLAvailable = true and return wrapped connection.
3. If PostgreSQL fails (Network timeout, DNS error, SSL failure):
   a. Mark isPostgreSQLAvailable = false.
   b. Record lastPostgresAttemptTime = current timestamp.
   c. Fallback to local SQLite driver (org.sqlite.JDBC) on niramaya_hospitals.db.
4. Return dynamic proxy wrapping Connection to log queries and intercept errors.

Module 2: Role-Based Authentication & Session Management (LoginHandler)
------------------------------------------------------------------------
1. Receive login payload (email, password, requestedRole).
2. Cleanse and lowercase email address; trim password string.
3. Compute SHA-256 hash of password.
4. Execute SQL query:
   SELECT * FROM users WHERE LOWER(email) = ? AND password = ?
5. If record found:
   a. Verify role match (case-insensitive).
   b. Update login_time in users and log event to activity_logs.
   c. Return user profile JSON (name, role, userId, phone, email) with HTTP 200.
6. If not found in database:
   a. Fall back to demo user registry in memory.
   b. If matching, return success; otherwise, return HTTP 401 Unauthorized.

Module 3: Doctor Availability & Queue Isolation (DoctorDAO.java)
----------------------------------------------------------------
1. Receive toggle request for doctorId with target status ("Online" or "Offline").
2. Execute SQL:
   UPDATE doctors SET status = ?, available_status = ?,
   appointment_available = (status == 'Online'),
   online_status_change_time = CURRENT_TIMESTAMP WHERE doctor_id = ?
3. When querying queue for Doctor X:
   SELECT * FROM appointments WHERE (LOWER(doctor_id) = ? OR LOWER(doctor_name) LIKE ?)
   AND UPPER(status) != 'CANCELLED' ORDER BY appointment_date DESC
4. Result: Doctor A can never view or manipulate appointments belonging to Doctor B.

Module 4: Counter Payment & Instant Receipt Unlocking (AppointmentDAO.java)
----------------------------------------------------------------------------
1. When patient books with "Pay at Counter":
   a. Generate AppointmentID ("TK-XXXX") and InvoiceID ("INV-XXXX").
   b. Insert into appointments with payment_status = 'Unpaid', status = 'Unpaid'.
   c. Mark receipt state as locked (receiptLocked = true).
   d. Dispatch notification to Admin Console queue: "Counter Payment Pending".
2. When reception collects cash/UPI at counter:
   a. Reception clicks "Collect & Mark Paid" in Admin Console.
   b. Execute SQL:
      UPDATE appointments SET payment_status = 'Paid', status = 'Confirmed'
      WHERE appointment_id = ?
3. Patient portal auto-polling detects status change and unlocks:
   "Print Official Tax Invoice & Receipt".

Module 5: Electronic Prescription (e-Rx) & Routing (PrescriptionsHandler)
-------------------------------------------------------------------------
1. Receive prescription data: diagnosis, medicine items list, doctor notes, follow-up.
2. Generate PrescriptionID ("RX-XXXXXX").
3. Persist record into prescriptions table.
4. Parse medicine schedule items:
   For each item, compute total quantity = (Morning + Afternoon + Night) * Days.
5. Auto-create Pharmacy Order:
   a. Generate PharmacyToken ("PH-XXXX").
   b. Insert order into pharmacy_orders with status = 'Prescription Received'.
   c. Insert line items into pharmacy_order_items.
6. If diagnostic tests are prescribed, auto-insert into lab_bookings.
7. Return prescription confirmation and routing acknowledgement.

Module 6: Pharmacy Stock Threshold & Expiry Tracking (StockManager.java)
-------------------------------------------------------------------------
1. Given medicine record (stockQuantity, minimumStock, expiryDate):
2. Parse expiryDate against current date:
   DaysLeft = (Date.parse(expiryDate) - CurrentDate) / (1000 * 60 * 60 * 24)
3. Evaluate Status:
   - If DaysLeft < 0                     -> Status = "Expired"
   - If 0 <= DaysLeft <= 60              -> Status = "Expiring Soon"
   - If stockQuantity <= 0               -> Status = "Out of Stock"
   - If 0 < stockQuantity <= minimumStock -> Status = "Low Stock"
   - Otherwise                           -> Status = "In Stock"
4. On medicine dispensing:
   Verify stockQuantity >= requestedQuantity. If true, subtract quantity and
   update stock_updated_at timestamp; if false, reject transaction.

Module 7: Laboratory Diagnostic Report Generation (PDFGenerator.java)
----------------------------------------------------------------------
1. Receive LabReport data containing test parameters, observations, and values.
2. Create unique output filename: Reports/LabReport_[PatientID]_[ReportID].pdf
3. Compile structured HTML template including:
   - Hospital NABL accreditation header.
   - Patient card (ID, Name, Age, Gender, Ref Doctor).
   - Test results table with normal biological reference intervals.
   - Abnormal values highlighted with clinical flags.
   - QR code verification payload.
   - Pathologist digital signature block.
4. Save file to Reports/ and public/Reports/ directories.
5. Update lab_bookings status to "Ready / Completed".

Module 8: Inpatient Ward Monitoring & Critical Vitals Triage (NurseDAO.java)
----------------------------------------------------------------------------
1. Nurse logs bedside vitals: BP (Systolic/Diastolic), Pulse, SpO2, Temperature.
2. Insert record into patient_vitals with timestamp.
3. Clinical Triage Evaluation:
   If SpO2 < 92% OR Systolic BP > 160 mmHg OR Pulse > 120 bpm:
   a. Flag as Critical Condition.
   b. Insert emergency record into emergency_alerts.
   c. Trigger visual alert on Nurse and Doctor dashboards.
4. Medication Administration Record (MAR):
   Record dose given, exact dosage_time, and nurse_id. If skipped, record
   mandatory missed_reason.

Module 9: Telemedicine Session Lifecycle (OnlineConsultationDAO.java)
---------------------------------------------------------------------
1. Fetch all consultations with status in ('Scheduled', 'Waiting', 'In Progress').
2. Parse scheduled_end and scheduled_start against current time.
3. If CurrentTime > scheduled_end + 30 minutes:
   Set meeting_status = 'Expired'.
4. When doctor and patient complete call:
   Calculate duration_minutes = (actual_end - actual_start) / 60000.
   Set meeting_status = 'Completed'.

Module 10: Database Manager & Audit Trail (DatabaseManagerDAO.java)
-------------------------------------------------------------------
1. Enforce admin role authentication.
2. For SQL queries:
   - Block destructive commands like DROP DATABASE.
   - If SELECT: execute query, parse ResultSetMetaData, and output JSON table.
   - If INSERT/UPDATE/DELETE: executeUpdate() and return affected rows.
3. Automatically log user_id, action, target module, and timestamp in activity_logs.

A. Dual-Database Connection & Automatic Failover (DBConnection.java):

public static Connection getConnection() throws SQLException {
    long now = System.currentTimeMillis();
    boolean hasPgEnv = System.getenv("POSTGRES_URL") != null || System.getenv("NEON_DB_URL") != null;
    if (isPostgreSQLAvailable || (hasPgEnv && (now - lastPostgresAttemptTime > POSTGRES_RETRY_INTERVAL_MS))) {
        try {
            Connection conn = getPostgreSQLConnection();
            if (conn != null) {
                isPostgreSQLAvailable = true;
                return conn;
            }
        } catch (Exception ex) {
            isPostgreSQLAvailable = false;
            lastPostgresAttemptTime = now;
            System.err.println("[DBConnection] PostgreSQL connection failed. Falling back to SQLite: " + ex.getMessage());
        }
    }
    try {
        Class.forName("org.sqlite.JDBC");
        Connection sqliteConn = DriverManager.getConnection(SQLITE_URL);
        return wrapConnection(sqliteConn, "SQLite (" + SQLITE_URL + ")");
    } catch (Exception sqliteEx) {
        throw new SQLException("CRITICAL: Failed to connect to Neon PostgreSQL and SQLite: " + sqliteEx.getMessage(), sqliteEx);
    }
}

C. Stock Expiry & Inventory Evaluation (StockManager.java):
----------------------------------------------------------
public static String calculateStatus(int stockQuantity, int minimumStock, String expiryDate) {
    try {
        if (expiryDate != null && !expiryDate.trim().isEmpty()) {
            SimpleDateFormat sdf = new SimpleDateFormat("yyyy-MM-dd");
            Date exp = sdf.parse(expiryDate.trim());
            Date today = new Date();
            long diffInMillies = exp.getTime() - today.getTime();
            long daysLeft = TimeUnit.DAYS.convert(diffInMillies, TimeUnit.MILLISECONDS);

            if (daysLeft < 0) return "Expired";
            else if (daysLeft <= 60) return "Expiring Soon";
        }
    } catch (Exception ignored) {}

    if (stockQuantity <= 0) return "Out of Stock";
    else if (stockQuantity <= minimumStock) return "Low Stock";
    return "In Stock";
}

public List<Appointment> getAppointmentsByDoctor(String doctorIdOrEmail) {
    List<Appointment> list = new ArrayList<>();
    String searchVal = doctorIdOrEmail.trim().toLowerCase();
    String sql = "SELECT * FROM appointments WHERE LOWER(doctor_id) = ? OR LOWER(doctor_name) LIKE ? ORDER BY appointment_date DESC";
    try (Connection conn = DBConnection.getConnection();
         PreparedStatement ps = conn.prepareStatement(sql)) {
        ps.setString(1, searchVal);
        ps.setString(2, "%" + searchVal + "%");
        try (ResultSet rs = ps.executeQuery()) {
            while (rs.next()) {
                list.add(mapResultSetToAppointment(rs));
            }
        }
    } catch (SQLException e) {
        System.err.println("Error fetching doctor appointments: " + e.getMessage());
    }
    return list;
}

10. DESCRIPTION OF THE WHOLE PROJECT
--------------------------------------------------------------------------------
Niramaya Hospital Management System (HMS) is a complete healthcare operations
and telemedicine platform that connects every department of a hospital into a
single unified digital ecosystem:

1. Patient Self-Service:
   Patients can browse doctors by specialty, book physical or telemedicine
   appointments, track live tokens, review e-prescriptions, and download invoices.
2. Clinical Suite for Doctors:
   Allows doctors to toggle their availability in real time, view assigned patient
   queues in isolation, write electronic prescriptions (e-Rx), and order lab tests.
3. Nurse Ward Management:
